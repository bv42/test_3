1. Overview 

A Python-based HTTP API agent for deploying applications to Windows servers in UAT and PROD environments. The agent runs as a Windows service and provides controlled deployment capabilities with audit logging. 
2. Core Requirements 
2.1 Functional Requirements 

     

    HTTP JSON API Endpoint
        Accepts POST requests with deployment payload 
        Returns deployment status and results 
        Supports both UAT and PROD deployments 
     

    Authentication & Authorization
        JWT-based authentication  

    Allow-list of usernames (simplified approach as requested) 
    Separate authorization rules for UAT vs PROD 

 

Deployment Validation

    UAT: Basic validation (app name, version, path) 
    PROD: Requires ServiceNow/ServiceFirst change request validation  

        Change request must be: fully approved, correct server/app details 
     

    Deployment Execution
        Integrates with existing internal deployment tooling 
        Supports rollback on failure 
        Maintains deployment audit trail 
     

    Operational Requirements
        Runs as Windows Service 
        Concurrent deployment prevention 
        Health monitoring endpoint 
        Comprehensive logging 

2.2 Non-Functional Requirements 

    Performance: Handle at least 10 concurrent deployments 
    Availability: 99.9% uptime during business hours 
    Security: JWT validation, input sanitization, path traversal prevention 
    Maintainability: Clean separation of concerns, comprehensive logging

4. Authentication & Authorization Flow 

     

    JWT Validation  

        Client obtains JWT from central auth service 
        JWT contains  sub (username) claim 
        Server validates JWT signature and expiration 
     

    Username Allow-list
        Simple list of authorized usernames 
        Configured via environment variable 
        No complex RBAC initially 
     

    Environment-based Rules
        UAT: Any authorized user can deploy 
        PROD: Additional change request validation required 

5. ServiceNow/ServiceFirst Integration  
5.1 Change Request Validation 

For PROD deployments only: 

     API Call: Query ServiceFirst for change request status 
     Validation Criteria: 
        Status = "APPROVED" 
        Fully approved (all approvals complete) 
        Target server matches current server 
        Application name matches deployment request 
        Change request is within valid timeframe 

5.2 Error Handling 

    Network timeout retries (3 attempts with exponential backoff) 
    Invalid change request → HTTP 400 with details 
    ServiceFirst API unavailable → HTTP 503 

6. Deployment Process 
6.1 Validation Phase 

     Input validation (JSON schema, path traversal check) 
     Authentication & authorization check 
     Environment-specific validation: 
        UAT: Basic checks 
        PROD: ServiceFirst validation  

     Concurrent deployment check (distributed lock) 

6.2 Execution Phase 

     Call existing internal deployment tooling 
     Monitor deployment progress 
     Capture output and exit code 
     Update deployment status 

6.3 Post-Deployment 

     Log deployment result 
     Send notification (optional) 
     Release deployment lock 
     Clean up temporary files

8. Test Cases 
8.1 Authentication Tests 

     
    Valid JWT with authorized user → HTTP 200 
     
    Valid JWT with unauthorized user → HTTP 403 
     
    Invalid/expired JWT → HTTP 401 
     
    Missing Authorization header → HTTP 401 

8.2 Input Validation Tests 

     
    Valid deployment request → HTTP 200 
     
    Missing required fields → HTTP 422 
     
    Invalid Windows path → HTTP 400 
     
    Malformed app name → HTTP 400 
     
    Invalid environment value → HTTP 400 

8.3 UAT Deployment Tests 

     
    UAT deployment without change request → HTTP 200 
     
    UAT deployment with valid credentials → Success 
     
    Concurrent UAT deployments → Second request fails

    PROD without change request → HTTP 400

    PROD with wrong target server → HTTP 400
